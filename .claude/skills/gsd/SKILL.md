# GSD — Get Shit Gone

Momentum mode. The goal is to move work from "open" to "gone" — done, verified,
and off the list — with the least ceremony that still keeps quality honest.
Optimize for shipping the right thing now over designing the perfect thing later.

This is the counterweight to `superpowers`: that skill adds rigor for large,
risky changes; GSD strips ceremony for well-understood work that just needs to
get done. Use GSD when the path is clear; use `superpowers` when it isn't.

## Operating principles

- **Bias to action.** When the next step is obvious, take it. Don't narrate
  options you won't pursue or ask permission for reversible, low-stakes moves.
- **Highest leverage first.** Do the thing that unblocks the most or delivers the
  most value now. Sequence by impact, not by what's easiest to start.
- **Ship in slices.** Deliver a working, verifiable increment fast, then iterate.
  A done small thing beats a perfect unfinished thing.
- **Time-box deliberation.** Decide with the info you have. If a choice is
  reversible and low-stakes, pick the sensible default and move — note it, don't
  convene a meeting about it.
- **Kill scope creep.** Do what was asked. Park nice-to-haves in a list instead
  of doing them mid-task.
- **Definition of done is non-negotiable.** Fast doesn't mean sloppy: the change
  must actually work and be verified before it's "gone".

## The loop

1. **Capture.** List the tasks/subtasks in play. Split anything vague into a
   concrete next action. Use the task tools to track a multi-step run.
2. **Prioritize.** Order by leverage: what unblocks or delivers most, first.
   Flag the one true blocker if there is one.
3. **Execute the top item.** Smallest correct change that finishes it. Don't
   yak-shave adjacent code.
4. **Verify quickly.** Run the relevant test/flow to confirm it's actually done —
   not just written. A quick real check, not a full audit unless warranted.
5. **Close it.** Mark it done, commit a coherent unit, move to the next item.
6. **Repeat** until the list is gone, then report what shipped.

## Guardrails (speed without recklessness)

- **Don't skip verification.** "Gone" requires evidence it works. Report failures
  honestly instead of declaring victory.
- **Don't fake completion.** No stubbing out the hard part, deleting the failing
  test, or marking done what isn't.
- **Don't barrel through real ambiguity or irreversible actions.** If a decision
  is genuinely the user's, or an action is hard to undo/outward-facing, stop and
  ask with `AskUserQuestion`. Speed applies to the reversible, not the risky.
- **Escalate a true blocker fast.** If something stops progress, surface it
  immediately with the diagnosis — don't grind silently or thrash.

## Reach for a specialist when the task calls for it

GSD is about pace and prioritization; pull in the right skill for the work
itself — `frontend-design` for UI, `web-app-testing` to verify a flow,
`self-healing` when something's red, `researcher` when you must find out first.
Then get it gone.

## Reporting

When the list is cleared, give a tight summary: what shipped, what was verified,
and anything intentionally parked for later. No filler — the results are the
report.
